Flight Simulation
By The MathWorks, Inc.
Create Project

This template illustrates how to create a project for an Aerospace Blockset specific project. It contains model-specific libraries, bus creation, linearization, testing, and initialization scripts.

The template:

  • Sets up the project working folder where generated code and other temporary files are created for the current project.
  • Recompiles the project S-functions.
  • Creates the initial condition variables for the flight dynamics simulation.

To start using the template follow these steps:

  1. Open nonlinearAirframe/nonlinearAirframe.slx in the project, and add your aircraft dynamics to the "AC model" subsystem under the "Nonlinear" subsystem.
  2. Add the relationship between the commands (i.e., joystick) and actuators (i.e., ailerons, motors, etc) in the controller/flightController.slx file.
  3. Add the initialization variables to the file startVars.m in utilities.

CubeSat Vehicle Model
CubeSat Vehicle Model
By The MathWorks, Inc.
Create Model

Aerospace Blockset lets you model, simulate, analyze, and visualize the motion and dynamics of CubeSats and nano satellites, which are miniaturized spacecraft designed for space research based on one or more 10cm cubes of up to 1.33kg per unit. This model template contains the CubeSat Vehicle block from asbCubeSatBlockLib.slx and a Spherical Harmonic Gravity Model from the Aerospace Blockset. Visualization using Simulink 3D Animation is provided if a valid license exists.

The CubeSat Vehicle block models a simple CubeSat vehicle:

  • Specify the initial orbital state as a set of Keplerian orbital elements; position and velocity state vectors in Earth-centered inertial axes; position and velocity state vectors in Earth-centered Earth-fixed axes; or latitude, longitude, altitude, and velocity of the body with respect to ECEF, expressed in the NED frame.
  • CubeSat attitude control is defined by alignment and constraint vectors. The CubeSat vehicle will align the primary alignment vector with the primary constraint vector. Then the CubeSat will attempt to align the secondary alignment vector with the secondary constraint vector. The block also contains preconfigured Earth Pointing and Sun Tracking attitude control modes.

Create Model
ROM
ROM
By The MathWorks, Inc.
Create Model

Create a model of a ROM using the Direct Lookup Table and Unit Delay Simulink blocks.
Follow these modeling guidelines when building a ROM:

  • For an n-bit address, specify all 2^n entries of the Lookup Table data. Otherwise, the synthesis tool may not map the generated code to RAM, and the code may not match your Simulink model.
  • Place the Lookup Table and Unit Delay blocks in the same model hierarchy.
  • Support of RAM reset logic varies among FPGA devices and synthesis tools. For best synthesis results, the generation of reset logic for the Unit Delay block is suppressed by setting its 'ResetType' parameter to 'none', in the HDL Block Properties dialog box. Also set the 'IgnoreDataChecking' property to 1 in the HDL Test Bench configuration parameters to ignore the initial simulation mismatch caused by the suppressing the reset logic.

Register
Register
By The MathWorks, Inc.

Shows how to model registers using delay blocks in Simulink, or persistent variables in a MATLAB Function block. Create a model of a register using either a Unit Delay block in Simulink or persistent variables in a MATLAB Function block.
A register is a group of flip-flops that stores a bit pattern. A register on the FPGA has a clock, clockenable, reset, input, and output data ports. Every clock cycle, the input data is latched, stored internally, and the output data is updated to match the internally stored data.
