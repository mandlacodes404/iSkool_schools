# iSkool Changelog

## [Unreleased]
### Added
- Teacher Dashboard (Desktop & Mobile): The login page's splash now carries straight through onto the teacher dashboard instead of vanishing into a blank dark page and then a spinner. `index.php` already starts one shared splash for every role and stores `splashStartedAt`, but the teacher dashboard had no splash of its own, so the handoff dead-ended and the flag was never cleared. The teacher page now paints an identical `#dash-splash` using the learner splash's colours (`#0a0a0a` desktop, `#20201f` mobile) rather than the teacher palette — the login page can't know the role yet, so a colour change mid-handoff would be the very flash this removes. It stays up until Home has actually rendered (a new `iskool:teacher-home-ready` event fired from `afterTeacherHomeRender()`, or the main content iframe's `load` event) and the remaining ~1300ms of the shared minimum has elapsed, whichever finishes last, with a 6s safety ceiling. The `splashStartedAt` flag is consumed on arrival, and on mobile the browser bar is held at `#20201f` for the duration and then handed back to the teacher `#0d1117` (`teacher_dashboard.php`, `teacher_dashboard.css`, `dashboard.js`).
- Teacher Dashboard (Mobile): Every teacher page now remembers where you scrolled to and puts you back there — when you return to it from another tab, after opening an item and pressing Back, and after a refresh. One central mechanism in `dashboard.js` remembers the scroll position of `#api-content-area` (the container that actually scrolls on phones) per view, so it applies to every teacher page without editing each section file. Positions are keyed by page and view (`<page>:list`) and held in `sessionStorage` (`teacherMobileScroll`). Only list views are remembered; every detail view opens at the top, so opening assignment #5 is never scrolled to wherever #2 was left. The position is applied before the first paint when the content is already there, keeps waiting (up to 4s) for content that arrives late, keeps re-applying for 500ms in case the layout settles afterwards, and stands down the moment a finger touches the page (`dashboard.js`).
- Learner Dashboard (Mobile): The same scroll memory for the learner side — Home, Quizzes, Assignments, Resources, Announcements, Evaluations and every other list page now return to where you left them after switching tabs, pressing Back from a detail view, or refreshing. Previously nothing was restored on phones: the section scripts (`assignments.js`, `quiz.js`, `resources.js`, `announcements.js`, `evaluations.js`) saved and restored `.main-content`'s scroll through `learnerPageState`, but on phones `#api-content-area` is the element that scrolls (`quiz.css` gives it `overflow-y: auto !important` on small screens), so the saved value was always 0 and Home came back at the top as well. The new mechanism remembers `#api-content-area` per view (`<lastLearnerPage>:list`, `sessionStorage` key `learnerMobileScroll`), keeps every detail view opening at the top, and leaves each section's own saved state — open folders, search text, selected item — working exactly as before (`learner_dashboard.php`).
- Teacher Dashboard (Mobile) & Learner Dashboard (Mobile): Tapping the bottom-nav or sidebar tab for the page you're already on now scrolls that page back to the top, and remembers it as the top so the saved position isn't restored over it. This listens on `pointerdown` rather than `click`, because by click time the page has already started loading and rewritten `lastTeacherPage` / `lastLearnerPage`, so "is this the page I was already on" can no longer be answered. Skipped while a detail view is open (`prepareTeacherMobileNavigation` in `dashboard.js`, `prepareLearnerMobileNavigation` in `learner_dashboard.php`).
- Teacher Dashboard (Mobile): Swipe gestures for the menu, using the same logic as the learner dashboard — swipe right from the left screen edge (a touch that starts within `28px` of it) to open the menu, swipe left while it's open to close it. A gesture must be more horizontal than vertical, has no minimum distance, and never blocks vertical scrolling. Rightward edge swipes are cancelled with `preventDefault()` on a non-passive `touchmove`, so the browser's own back-navigation / reload gesture can't take the touch over — this is the fix for the intermittent "swiped to open the menu and the app navigated back / refreshed". `overscroll-behavior-x: none` is also set on `html`, `body` and `#api-content-area` at `<=768px`, because in the first few pixels of a touch the OS gesture can win the race against JavaScript. Two deliberate differences from the learner: it applies at mobile widths only, so desktop trackpad swipe-back is untouched, and `overscroll-behavior-y` is left alone — the learner sets it to `contain` for its own custom pull-to-refresh, and the teacher page has none, so native pull-to-refresh keeps working. The listeners are registered at every width and check `window.innerWidth <= 768` when they fire, so rotating or resizing into mobile width works without a reload (`initTeacherMenuSwipe` in `teacher_dashboard.php`, `teacher_dashboard.css`).
- Teacher Dashboard (Mobile & Desktop): The school logo in the top nav now falls back to a school-initials avatar when the school hasn't uploaded a logo, the same as the learner dashboard's `.school-logo-initials`. Initials come from the first two words of the school name ("Thoko Thaba Highschool" → `TT`, `??` if the name is empty) and sit in a rounded square with a `0.5px` hairline rim, `Nunito` 800, `#9a9a97`, at the same `36px` footprint as the `<img>` it stands in for, so the header height and spacing don't change. The background is applied the way the learner applies it — a solid, hard-coded fill equal to the surface the avatar sits on (the learner's carries `background: #20201f`), not `transparent`: `var(--bg-color)` (`#0d1117`) on mobile and `#12161c`, the top-nav colour, on desktop (`min-width: 769px`). As on the learner, the fill is a fixed colour and doesn't follow the header when a page's signature colour tints it on scroll, so the avatar stays a solid chip in the base colour. A placeholder (`default_school.png`, or an empty value) or a saved path whose file is no longer on disk (`is_file`) counts as "not uploaded", so a broken-image icon never shows. The element keeps its `id="teacherHeaderLogo"` either way (`teacher_dashboard.php`, `teacher_dashboard.css`).

### Changed
- Teacher Dashboard (Mobile): The pill loader overlay (`#loaderOverlay`) no longer appears over Home on a cold load right after login. While the splash handoff is running, `window.suppressInitialLoader` is set, `loadTeacherManual()` skips turning the loader on, and a `<=768px` rule (`html.splash-handoff #loaderOverlay`) hides it, so the sequence is one continuous splash instead of splash → blank page → spinner → Home. Loaders for later, in-session navigation are unchanged. This mirrors the learner side's `suppressInitialLoader` (`dashboard.js`, `teacher_dashboard.css`, `teacher_dashboard.php`).
- Teacher Dashboard (Mobile) & Learner Dashboard (Mobile): The header tint, browser-bar colour (`theme-color`) and bottom-nav glass now change together with the scroll position, in one step before the first paint, when you arrive on a page. `recalcTeacherMobileScrollUI()` and `recalcMobileScrollUI()` judge them by the position the incoming page is about to be restored to (`window._teacherPendingScroll` / `window._learnerPendingScroll`) instead of wherever the outgoing content happened to be scrolled. `configureTeacherHeader()` announces the incoming view (`teacherBeginViewTransition`) so the state is already correct by the time the content lands, and the `0.28s` background transitions on the header and bottom nav are switched off just for the page switch (a `teacher-nav-snap` / `learner-nav-snap` class on `<html>`, with its style injected by the script) so they snap to the final look instead of fading through the wrong one. Normal scroll-driven fades are unchanged (`dashboard.js`, `learner_dashboard.php`).
- Learner Dashboard (Mobile): `configureHeader()` now finishes by announcing the incoming view (`learnerBeginViewTransition`) and recalculating the mobile scroll UI. Previously it set the browser bar to a flat `#20201f` on every page change and left the real tint to a later scroll event, so a page arriving already scrolled showed the wrong bar colour first. The Progress Report full-screen sheet guard (dark header and bar while `.pr-modal-overlay` is open) is unchanged (`learner_dashboard.php`).
- Learner Dashboard (Mobile): When a page has a remembered scroll position, its content is now kept invisible for the few milliseconds until that position can actually be applied, then revealed the moment it lands (never held for more than `350ms`, `HIDE_MAX_MS`). The learner sections render first and reopen the folders you had open one frame later, so without this the first painted frame showed the page collapsed at the top before jumping down (`learner_dashboard.php`).
- Teacher Dashboard (Mobile Home): The class list now holds its last known height while it loads (`min-height` taken from `sessionStorage` key `teacherHomeClassListH`, cleared and re-measured once the real list arrives). Home fetches its classes after first render into a nested element, so it was too short to scroll back to where you left it and the position could only be restored after a visible jump; now it lands immediately. `loadMobileHomeClasses()` wraps the original loader (`_loadMobileHomeClassesInner`) to do the measuring (`dashboard.js`).
- Teacher Dashboard (Mobile): The opened mobile menu now looks like the learner dashboard's. Geometry: the menu is `79%` of the screen width, capped at `340px` (was a fixed `300px`, and `80%` at `<=480px`), and the page slides across by the same `min(79vw, 340px)` and blurs by `2px` (was `300px` / `80vw` and `3px`). Curved edge: `#mobileOverlay` is a sibling of `.main-content`, so `.main-content`'s blur doesn't reach it; while the menu is open (`.sidebar.active ~ #mobileOverlay`) it now starts exactly where the menu's straight edge ends and gets `35px` top-left and bottom-left corners with a `1px solid #555555` rim on the left, top and bottom, which is the outward curve you see. Its `backdrop-filter: blur(6px)` is switched off while open, since a backdrop blur would soften that edge, and it is given `z-index: 4500` — above `#mobileBottomNav` (`4000`) so the bottom corner isn't covered by the bottom bar, below the menu (`5000`). The `rgba(0,0,0,0.55)` dim is unchanged. Corner blend: the sliver between each curve and the screen corner shows whatever sits behind the overlay, so `body.menu-open { background: #1a1919 }` (mobile only, class toggled by `toggleSidebar()` / `closeMobileSidebar()`) makes it the menu's own colour and the corners look carved out of the menu. No colours changed, and desktop is untouched (`teacher_dashboard.css`, `teacher_dashboard.php`).
- Teacher Dashboard (Mobile): While the menu is open, the header (`.top-nav-wrapper`) is now recoloured to the menu colour (`SIDEBAR_THEME_COLOR`, `#1a1919`), and whatever inline background it had is kept in `data-bg-before-menu` and put back exactly on close. Without this, a page's signature colour (e.g. Assignments purple) showed beside the open menu and broke the curved edge. This is the same mechanism as the learner's `bgBeforeMenu`. `closeMobileSidebar()` also now restores the browser bar (`theme-color`) to the page's signature colour when the header is scrolled on a coloured page, falling back to `#0d1117`; before, it always reset to `#0d1117` (`teacher_dashboard.php`).
- Teacher Dashboard (Mobile): The `iSkool` version footer in the mobile menu now has the same thickness and brightness as the learner's. Both pages use the same CSS, but the learner page only downloads Nunito `600`, so its `<strong>` (`400`) falls back to that `600` face and renders semi-bold, while the teacher page downloads `200`–`600` and got a genuinely thinner `400`. The footer and its `<strong>` are now `font-weight: 600` at `<=768px`. Opacity is matched too — `0.6` up to `768px` and `0.8 !important` on phones (`<=480px`), like the learner (it was `0.7` at every width). Desktop is unchanged (`teacher_dashboard.css`).
- Teacher Dashboard (Mobile & Desktop): The top-nav school logo now shows the school's uploaded logo when there is one. `$schoolLogo` was hard-coded to `uploads/schools/default_school.png?v=1.1` and the `school_logo` column was never read on this page, so the teacher header always showed the shared placeholder even for schools that had uploaded a logo. It now reads `school_logo` the same way `learner_dashboard.php` does (`teacher_dashboard.php`).
- Teacher Dashboard: Cache-busting `?v=` values on the page's own assets bumped so phones re-download them instead of serving cached copies — `teacher_dashboard.css?v=20260921.2` and `dashboard.js?v=20260920` (`teacher_dashboard.php`).

### Fixed
- Teacher Dashboard (Mobile Home): Fixed Home keeping the previous section's signature colour in the header and browser bar. Every other teacher page calls `configureTeacherHeader`, which sets or clears the colour, but Home never did, so after visiting Assignments (purple), Resources or any other coloured section, Home showed that section's tint. `loadTeacherManual()` now calls `configureTeacherHeader({ mode: 'standard' })` with no colour, which clears back to the base surface (`dashboard.js`).
- Teacher Assignments (Mobile): Fixed the list always coming back at the top after opening an item and pressing Back, or after switching tabs and returning. The section wired its scroll restore to `.as-sidebar-scroll`, the desktop sidebar, which is hidden on phones, so on mobile nothing was ever saved or restored while the list was rebuilt from scratch each time. Covered by the central scroll memory above; the desktop sidebar scroll save/restore (`saveTeacherScrollState` / `restoreTeacherScrollState`) is untouched (`dashboard.js`).
- Teacher Dashboard (Mobile): Fixed the header and browser bar flickering, and looking slow, when switching to a page whose scroll position is restored. Touching a nav link used to reset the scroll position, header tint and browser bar to their "at top" look immediately, and the remembered position was only re-applied 100-700ms later, so the header faded out and back in over its `0.28s` transition and the browser bar went dark before returning to the page's colour. The old page also visibly jumped to the top before the new one appeared. Nothing now moves until the new page is ready, and then scroll position, header, browser bar and bottom nav switch together. The learner dashboard had the same touch-time reset and gets the same change (`dashboard.js`, `learner_dashboard.php`).
- Teacher Dashboard (Mobile): Fixed the header (hamburger, logo and avatar) being pushed completely off-screen while the menu was open — it ended up at roughly `x = 624` on a 390px screen. `.top-nav-wrapper` is `position: fixed` inside `.main-content`, and a transformed ancestor becomes the containing block for its fixed descendants, so `.main-content`'s `translateX` was already carrying the header across; a second `translateX` on the header itself moved it again. It now travels with `.main-content` once and stays visible (dimmed) beside the menu, as on the learner (`teacher_dashboard.css`).
- Teacher Dashboard (Mobile): Fixed the bottom-left curve of the open menu not blending with the menu the way the top-left one does (seen as a pale smudge on a real iPhone). The top corner was clean because the header is recoloured to the menu colour on open, but `#mobileBottomNav` kept its own lighter glass fill (`rgba(66,65,65,0.35)`), which showed through the gap between the curve and the screen corner. While the menu is open the bottom bar is now painted `#1a1919` with its backdrop blur off, which also avoids iOS compositing artefacts against its own `blur(5px)` filter; on close it returns to its normal glass (`teacher_dashboard.css`).
- Teacher Dashboard (Mobile): Fixed a page's colour being painted over the open menu's header. `recalcTeacherMobileScrollUI()` already skipped the browser-bar colour while the menu is open, but it still repainted the header background, so any scroll, `MutationObserver` or timed recalculation firing mid-open put the page colour back beside the menu. The header background is now skipped while the menu is open too, and the value to restore on close is kept current in `data-bg-before-menu`, so closing lands on the right colour even if the page was scrolled in between (`dashboard.js`).

### Removed
- Learner Dashboard (Mobile): Removed the scroll reset, header-tint clear and bottom-nav force-show that ran on every nav-link touch (`touchstart`) and again on click (`prepareLearnerMobileNavigation`, called from `handleLearnerMobileBottomNav` and from the nav click handler). That work now happens once, on arrival, as described above; `prepareLearnerMobileNavigation` only handles tapping the tab you're already on (`learner_dashboard.php`).
- Teacher Dashboard (Mobile): Removed the extra `.sidebar.active ~ .main-content .top-nav-wrapper { transform: translateX(...) }` rules (`300px` in the `<=768px` block, `80vw` in the `<=480px` block, the first also carrying `filter: blur(3px)`) — the duplicate shift described under Fixed above (`teacher_dashboard.css`).

## [v1.2.5] - 2026-09-11
### Added
- Teacher Announcements: Teachers can now edit the title and message of a class-level announcement they've already sent (school-wide announcements from admin remain read-only from this view). A new "Edit" button sits next to "Delete" in the announcement panel and opens the same form used for composing a new announcement, pre-filled with the current title/message (`edit_announcement.php` — new file, `announcements.js`, `announcements.css`).
- Learner & Teacher Announcements: An edited announcement now shows an "Edited" tag next to its title (sidebar item, mobile card, and detail/panel view) plus an "Edited <date>" line, so it's clear the message has changed since it was first sent (`get_announcements.php` for both roles, `announcements.js`/`announcements.css` for both roles).
