# iSkool Changelog

## [Unreleased]
### Changed
- Learner Dashboard (Mobile): Reworked pull-to-refresh to behave like a native app: the current page follows the pull with resistance, stays held down while refreshed content loads, then smoothly returns to its resting position. The refresh spinner now sits in the temporary gap above the pulled-down page rather than overlapping the content; it uses eight thicker, fully visible rounded pills rotating at a slower speed. Native vertical overscroll is contained so it cannot compete with the custom interaction (`learner_dashboard.php`, `learner_dashboard.css`).
- Learner Discussions (Mobile): Added Discussions to the pull-to-refresh page map, so refreshing the discussion list now reloads its data instead of falling back to the Home page (`learner_dashboard.php`).

### Fixed
- Learner Discussions (Mobile): Fixed the pull-to-refresh indicator appearing while scrolling through older chat messages. Discussion threads use their own message scroller, which is now excluded from the page-level refresh gesture (`discussions.js`, `learner_dashboard.php`).

### Fixed
- Learner Dashboard (Desktop): Fixed a double header and a broken "Leave Quiz" flow introduced by loading `take_quiz.php` inside the dashboard's iframe — the quiz's own topbar was stacking underneath the dashboard's header, and its exit button was reloading the entire dashboard shell instead of returning to the quiz list. Start/Continue Quiz now do a normal full-page navigation to `take_quiz.php`, the same way the old instructions screen's form used to, restoring correct single-header rendering and a working exit (`quiz.js`).
- Learner Dashboard (Mobile): Fixed the mobile bottom nav sometimes loading a blank page when tapped mid-scroll — momentum scrolling is now stopped and the content scroll position reset before the next page loads, with the header/bottom nav state refreshed on the next animation frame; also fixed the bottom nav active-state keys for Assignments (`assignment_list.php`) and Resources (`resource_list.php`) (`learner_dashboard.php`).
- Learner Calendar: Fixed the mobile layout so the calendar panel stretches to fill the full width of the screen instead of being cramped on the left with empty space on the right (`learner_calendar.js`).
- Login: Reduced the gap between the end of the splash screen (or a successful login) and the dashboard actually being ready, for "remember me" users. The dashboard was previously never touched until the redirect fired, so its full PHP/DB work and ~10 CSS/font requests always started from cold. Logged-in sessions now get `<link rel="preload">`/`preconnect` hints for the dashboard's stylesheets and fonts rendered during the splash screen, plus a background `fetch('dashboard')` fired at the start of the splash window so the dashboard's server-side work runs in parallel with the splash instead of after it; a fresh login also starts preloading the dashboard's static assets the moment the form is submitted, before the login result is even known. Splash duration and all its timing/visual behaviour are unchanged — this only uses the idle time within it (`index.php`).
- Learner Dashboard (Desktop): Fixed the slide-out menu stuttering on its first open each session (subsequent opens were already instant). Two causes stacked in the same animation frame: the dimming backdrop's `backdrop-filter: blur(6px)` had its GPU compositing layer created for the first time on that first open instead of at page load, and the sidebar was sliding via `left` (a layout property that forces reflow/repaint every frame) instead of `transform`. Backdrop now gets `will-change: opacity` so its blur layer is built ahead of time, and the sidebar's slide is now driven entirely by `transform: translateX()`, matching the GPU-composited approach already used on mobile. Mobile behaviour is unchanged (`learner_dashboard.css`).
- Learner Dashboard (Mobile): Fixed Home having extra empty space to scroll through at the bottom compared to every other page — its `.lh-mobile-wrapper` was adding its own flat 90px of bottom padding on top of `#api-content-area`'s existing bottom-nav clearance (`calc(80px + safe-area)`, shared across all mobile pages via `quiz.css`), reserving space for the same nav bar twice. Trimmed to a plain 16px, matching the wrapper's own side padding (`manual.css`).

- UI: Removed borders from icon boxes in Grades (`grades.js`) — mobile quiz-row icons (including the unpublished-quiz state) and the printable Progress Report's subject icons (including the performance-colored variant). Background colors kept.
- Learner Dashboard (Mobile): Reworked the slide-out menu to match the X (Twitter) app's mobile menu style — widened from a fixed 300px to 79% of the viewport (capped at 340px), removed the menu's own rounded corner in favour of an inward curve (35px radius) on the dimmed area behind it, with a matching border seam that only appears while the menu is open; the curve/seam live on `#mobileOverlay` rather than the blurred `.main-content`, since a `filter: blur()` on an element also blurs its own border/radius, which was making an earlier attempt look like a smudged straight line instead of a clean curve (`learner_dashboard.css`). Desktop untouched.
- Learner Dashboard (Mobile): Fixed the dimmed corner/seam above not appearing at the bottom of the screen — `#mobileOverlay`'s z-index sat below the bottom nav bar's, so the nav bar was rendering on top of it there; raised the overlay above the bottom nav (still below the menu itself) (`learner_dashboard.css`).
- Learner Dashboard (Mobile): Reduced how often the swipe-to-open-menu gesture conflicts with the browser's own native edge-swipe (which was intermittently reloading the app or navigating back instead of opening the menu) by adding `overscroll-behavior-x: none` on `html`, `body`, and the scroll container — a browser-level setting that wins the gesture race more reliably than the existing `preventDefault()`-based JS alone. Only the horizontal axis is affected, so pull-to-refresh (a vertical gesture) is unaffected; not fully eliminated on iOS Safari specifically, which treats edge-swipe-back as a stronger system gesture (`learner_dashboard.css`).
- Learner Dashboard (Mobile): The browser bar (`theme-color`) and the top header now switch to the menu's own dark colour while the slide-out menu is open, instead of keeping whatever colour the current page had (e.g. Announcements' accent), so the whole screen reads as one consistent dark surface; both revert to the page's correct colour when the menu closes. The header's own background is swapped directly (its saved prior value is restored on close) rather than blurred, since it sits nested inside `.main-content` with its own `position:fixed` stacking context and doesn't inherit its parent's blur filter (`learner_dashboard.php`).
- Learner Dashboard (Mobile): The avatar dropdown (opened by tapping the header avatar) now uses the app's actual dark surface colour (`#20201f`) instead of a mismatched leftover dark-slate colour (`#161b22`) that didn't match the rest of the app's palette; desktop keeps the original colour (`learner_dashboard.css`).
- Learner Dashboard (Mobile): Fixed the bottom nav (and top header) sometimes showing the wrong background after switching pages — their transparent/solid state was only ever recalculated on a real scroll event, and the synthetic scroll dispatch fired on page-switch was checking scroll position before that page's content had actually rendered, so the check ran against stale/empty content. An initial fix recalculated once the shared loading spinner (`#loaderOverlay`) hides, but most page switches hit an already-cached page and swap content in instantly with no spinner shown at all, so that signal frequently never fired. Replaced with a short burst of rechecks (over ~500ms) directly inside the shared mobile navigation handler that runs on every page switch regardless of cache state or spinner visibility, so it now self-corrects reliably either way (`learner_dashboard.php`).
- Learner Dashboard (Mobile): Fixed the same stale bottom-nav/header background issue when expanding or collapsing a teacher folder, or filtering the list via search, on Assignments, Announcements, Quiz, Evaluations, and Resources — both actions change the page's actual scrollable height without firing a real scroll event, so the nav could stay stuck showing whatever background it had before the folder opened/closed or the search ran. The shared recalculation logic was exposed globally (`window.recalcMobileScrollUI`, from `learner_dashboard.php`) and is now called with the same short recheck burst from each page's folder-toggle and search functions (`assignments.js`, `announcements.js`, `quiz.js`, `evaluations.js`, `resources.js`).

### Removed
